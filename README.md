# Сбор корпоративных переписок в Telegram

Система автоматически сохраняет переписку в рабочих Telegram-чатах и позволяет
администраторам выгружать её за произвольный период. В чат добавляется
бот-коллектор, который пишет каждое сообщение в PostgreSQL и складывает
вложения на диск. Отдельный админский бот отдаёт эти данные: сообщения — JSON-файлом,
вложения — ZIP-архивом.

Зачем два бота: у них разные задачи и разные зоны доступа. Коллектор сидит в
групповых чатах и только пишет в базу, выгружать через него ничего нельзя.
Админский бот работает в личке, никогда не добавляется в рабочие чаты и отвечает
только пользователям из списка администраторов. Даже если токен коллектора
утечёт, выгрузить им архив переписки не получится.

## Что сохраняется

- текст сообщений и подписи к файлам;
- документы, фото, видео, гифки, голосовые, видеосообщения, аудио — файл скачивается
  в `storage/attachments/<telegram_chat_id>/`, в базе лежит относительный путь к нему,
  а рядом размер и — у голосовых, кружков, видео и аудио — длительность записи;
- автор сообщения: Telegram ID, username, имя и фамилия;
- время отправки и время последней правки;
- ссылка на сообщение, которому отвечают, — иначе ветки обсуждения в выгрузке
  рассыпаются в плоский список;
- **история правок**: при редактировании прежний текст не затирается, а уходит
  в таблицу `message_versions`. При разборе спорных ситуаций обычно интересна
  как раз первая формулировка, а не итоговая;
- **происхождение пересылки**: у пересланного сообщения в авторах стоит тот, кто
  переслал, поэтому исходный источник сохраняется отдельно — человек, скрытый
  автор, чат или канал. Иначе чужие слова в выгрузке выглядят как слова
  пересылавшего;
- **служебные события** в таблице `chat_events`: кто вошёл и по чьей воле, кто
  вышел сам и кого исключили, смена названия и фото, закрепления, переезд группы
  в супергруппу. Для аудита состав участников и момент входа важны не меньше
  самой переписки.

Стикеры не сохраняются: содержания в них нет.

## Архитектура

Четыре независимых модуля, связанных только через общую базу данных. Ни один
не импортирует другой — коллектор ничего не знает о выгрузке, админский бот
ничего не знает о сборе.

| Модуль | Каталог | Задача |
| --- | --- | --- |
| Интеграция с БД | `app/db/` | Модели SQLAlchemy и CRUD-функции |
| Сбор данных | `app/collector/` | Слушает чаты, пишет сообщения и вложения |
| Администратор | `app/admin_bot/` | Диалоги выгрузки, проверка прав |
| Общий модуль | `app/main.py` | Запускает коллектор и админского бота в одном процессе |

Общие мелочи вынесены отдельно, чтобы модули не тянули друг друга: пути к каталогам
проекта — в `app/paths.py`, общие шаги диалогов админского бота — в
`app/admin_bot/handlers/common.py`.

## Стек

aiogram 3 (Telegram Bot API), SQLAlchemy 2, PostgreSQL, python-dotenv.
Разрабатывалось на Python 3.14, минимальная версия для aiogram 3 — 3.9.

## Установка

```bash
git clone https://github.com/Saichiro21/Work.git
cd Work

python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Создайте базу данных в PostgreSQL:

```bash
createdb -U postgres work
```

Таблицы создавать вручную не нужно — `app/main.py` вызывает `init_tables()` при запуске.

Учтите, что `init_tables()` добавляет только отсутствующие таблицы: новые колонки
в уже существующие он не дописывает. Если база создана более ранней версией
проекта, колонки нужно добавить один раз вручную:

```bash
psql -U postgres -d work <<'SQL'
ALTER TABLE messages ADD COLUMN IF NOT EXISTS reply_to_message_id BIGINT;
ALTER TABLE messages ADD COLUMN IF NOT EXISTS forward_origin_type VARCHAR;
ALTER TABLE messages ADD COLUMN IF NOT EXISTS forward_from_name VARCHAR;
ALTER TABLE messages ADD COLUMN IF NOT EXISTS forward_from_id BIGINT;
ALTER TABLE messages ADD COLUMN IF NOT EXISTS forward_origin_date TIMESTAMP;
ALTER TABLE messages ADD COLUMN IF NOT EXISTS is_automatic_forward BOOLEAN NOT NULL DEFAULT FALSE;
ALTER TABLE attachments ADD COLUMN IF NOT EXISTS file_size BIGINT;
ALTER TABLE attachments ADD COLUMN IF NOT EXISTS duration_seconds INTEGER;
-- Путь пустой у вложений, файл которых скачать не удалось
ALTER TABLE attachments ALTER COLUMN file_path DROP NOT NULL;
SQL
```

Таблицы `message_versions` и `chat_events` создадутся сами при запуске.

## Переменные окружения

Все секреты читаются из `.env` через `load_dotenv()`. Скопируйте шаблон и заполните:

```bash
cp .env.example .env
```

| Переменная | Обязательна | Описание |
| --- | --- | --- |
| `DB_HOST` | да | Хост PostgreSQL, обычно `localhost` |
| `DB_PORT` | да | Порт, по умолчанию `5432` |
| `DB_NAME` | да | Имя базы данных |
| `DB_USER` | да | Пользователь PostgreSQL |
| `DB_PASSWORD` | да | Пароль пользователя |
| `COLLECTOR_BOT_TOKEN` | да | Токен бота-коллектора от @BotFather |
| `ADMIN_BOT_TOKEN` | да | Токен админского бота, отдельный от коллектора |
| `ADMIN_IDS` | да | Telegram ID администраторов через запятую |
| `COLLECTOR_CHAT_IDS` | нет | Белый список чатов: `telegram_chat_id` через запятую. Если пусто, коллектор пишет сообщения из всех групп, куда его добавили |
| `DISPLAY_TIMEZONE` | нет | Часовой пояс для показа времени в выгрузках, например `Europe/Moscow` или `Asia/Shanghai`. Без него берётся пояс самой машины — в нём же время видно и в Telegram. Задавать стоит, когда сервер живёт в UTC, а выгрузку читают в своём поясе |

`ADMIN_IDS` при каждом запуске синхронизируются в таблицу `admins`, так что
достаточно дописать ID в `.env` и перезапустить процесс. Свой ID можно узнать
у @userinfobot.

Файл `.env` в `.gitignore` и в репозиторий попасть не должен.

## Настройка ботов

**Бот-коллектор.** Создайте бота у @BotFather, затем обязательно отключите privacy mode:
`/mybots` → выберите бота → `Bot Settings` → `Group Privacy` → `Turn off`. Без этого
Telegram будет присылать боту только сообщения, где его упомянули, и сбор работать
не будет. После этого добавьте бота в рабочий чат.

**Админский бот.** Создайте второго бота, его токен положите в `ADMIN_BOT_TOKEN`.
В группы его добавлять не нужно, он работает только в личных сообщениях.

Описание, подпись в профиле и меню команд бот ставит себе сам при каждом запуске
(`publish_profile` в `app/admin_bot/bot.py`), в BotFather их задавать не нужно.
Описание — это тот экран с кнопкой «Старт», который человек видит в пустом чате
до первого сообщения; позже его же показывает кнопка «Что умеет этот бот?».
Команды в нём берутся из того же списка, что и приветствие, так что разъехаться
не могут. Чтобы увидеть экран заново, очистите историю переписки с ботом.
Если Telegram откажет (например, ограничит частоту запросов), бот напишет
предупреждение в лог и продолжит работать: на сбор и выгрузку это не влияет.

**Как узнать `telegram_chat_id` чата.** Оставьте `COLLECTOR_CHAT_IDS` пустым,
запустите проект и напишите в чат любое сообщение. После этого ID можно взять
у админского бота: `/export` → «Показать список чатов» → «Показать ID чатов»,
номера там оформлены для копирования одним нажатием. Тот же список есть в базе:

```bash
psql -U postgres -d work -c "SELECT telegram_chat_id, title FROM chats;"
```

Нужный ID можно затем вписать в `COLLECTOR_CHAT_IDS`, чтобы бот игнорировал
остальные чаты. У обычных групп ID отрицательный, у супергрупп начинается с `-100`.

Если обычная группа превращается в супергруппу, её `telegram_chat_id` меняется,
и старый номер в `COLLECTOR_CHAT_IDS` перестаёт совпадать — сбор по такому чату
прекратился бы молча. Коллектор ловит этот момент, пишет новый ID в лог
предупреждением и сохраняет событие в `chat_events`.

## Запуск

```bash
python -m app.main
```

Поднимаются обе задачи сразу, через `asyncio.gather`. Если одна падает, вторая
корректно останавливается, а не остаётся висеть в процессе. Остановка — `Ctrl+C`.

Модули можно запускать и по отдельности, это удобно при отладке:

```bash
python -m app.collector.runner
python -m app.admin_bot.bot
```

### Автозапуск через systemd

Запуск из терминала живёт ровно до закрытия окна, поэтому для постоянной работы
в репозитории лежит готовая служба `deploy/telegram-archive.service`. Пути в ней
указаны для `/home/sai/projects/work` — поправьте под себя.

```bash
mkdir -p ~/.config/systemd/user
cp deploy/telegram-archive.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now telegram-archive
```

Служба поднимается заново после любого падения — сеть и Telegram отваливаются
регулярно, это нормальный режим работы.

Отсюда важное: пока служба включена, запускать бота руками из терминала нельзя.
Двух экземпляров с одним токеном Telegram не допускает — в логах пойдёт
`TelegramConflictError`, а обновления начнут доставаться то одному, то другому.
`pkill` тут не помогает: служба тут же поднимет процесс обратно. Чтобы
запуститься руками, службу надо сначала остановить:

```bash
systemctl --user stop telegram-archive     # перед запуском из терминала
systemctl --user restart telegram-archive  # обычный способ подхватить правки
```

Состояние и логи:

```bash
systemctl --user status telegram-archive
journalctl --user -u telegram-archive -f
```

Осталась одна команда, которую нужно выполнить от root: без неё пользовательские
службы останавливаются, когда закрыт последний терминал.

```bash
sudo loginctl enable-linger $USER
```

В WSL нужен ещё включённый systemd — в `/etc/wsl.conf` должно быть:

```ini
[boot]
systemd=true
```

После правки `wsl.conf` выполните в PowerShell `wsl --shutdown` и откройте
терминал заново. PostgreSQL при этом должен запускаться сам
(`sudo systemctl enable postgresql`), иначе бот будет перезапускаться по кругу,
пока база не поднимется.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты не трогают ни настоящую базу, ни Telegram: под каждый тест поднимается
пустая SQLite в памяти, а служебные сообщения собираются из сырых словарей —
ровно так, как их разбирает aiogram из ответа Telegram. Проверяются разбор
периода, сборка JSON и HTML-страницы, операции с базой, распознавание служебных
событий, работа с вложениями, учёт экранов диалога и описание бота в Telegram.
Отдельно проверены шаги `/export` целиком — от присланного периода до файла:
склейка шагов ломается не там, где ломаются отдельные функции.

## Как выгрузить данные

Напишите админскому боту в личку. Пользователям не из `ADMIN_IDS` бот не отвечает вообще.

- `/start` — список команд.
- `/export` — переписка чата за период: HTML-страница или JSON-файл.
- `/files` — вложения этих сообщений в виде ZIP-архива.

`/export` и `/files` спрашивают одно и то же в два шага: сначала `telegram_chat_id`
чата, потом период в формате `14.09.2026 - 14.09.2026`. Последний день входит
в выборку целиком, до `23:59:59`. Регистр команд не важен, `/Export` сработает
так же, как `/export`.

`/export` добавляет третий шаг — в каком виде выгружать. На экране сразу видно,
сколько нашлось, так что файл можно и не заказывать. Формата два, и они для
разного: HTML открывают и читают глазами, JSON отдают системе. Подробнее
о странице — в разделе «HTML-страница» ниже.

`/files` добавляет к этому третий шаг — какие вложения нужны. На экране видно,
сколько чего нашлось за период, а выбрать можно всё, только документы или
картинки. Кружки отнесены к звуку, а не к видео: в переписке они звучат как
голосовые, поэтому после «Фото и видео» бот отдельно спрашивает, нужны ли
голосовые. Фильтр экономит не столько время, сколько размер: без видео
и голосовых архив обычно перестаёт разрезаться на части.

Период можно назвать одной датой: `16.09.2026` — это тот же день с начала до конца,
и в имени файла он тоже останется одной датой. Диапазон пишется через дефис,
пробелы вокруг него необязательны.

Ввод проверяется по порядку: сначала формат, затем существование дат и то, что
период не целиком в будущем, и только потом выполняется запрос. Если за период
сообщений нет, бот так и отвечает, пустой файл не присылается.

Присланные даты остаются в переписке, а замечание приходит под ними и заменяет
собой вопрос: разбираться в ошибке проще, когда своя строка на виду. Формат при
этом не теряется — либо он в замечании примером, либо присланное уже было
правильного вида, и дело не в формате. Прошлые попытки и ответы на них тоже
остаются: это история запроса, кнопки живут только в нижнем окне. Если период
разобран, но данных за него нет, вместо пустого файла приходит экран с выходами:
назвать другие даты, вернуться к выбору чата или в меню.

Пример диалога:

```
Вы:  /export
Бот: /export — переписка файлом
     Из какого чата взять данные?
     [ Показать список чатов ][ Показать ID чатов ]
     [ Назад ]

Вы:  нажали «Показать список чатов»
Бот: Выберите чат из списка:
     [ Назад ]
     [ Отдел разработки ]
     [ Продажи ]

Вы:  нажали «Отдел разработки»
Бот: За какой период? Введите дату ДД.ММ.ГГГГ или диапазон ДД.ММ.ГГГГ - ДД.ММ.ГГГГ
     [ К выбору чата ][ В главное меню ]

Вы:  01.09.2026 - 14.09.2026
Бот: В каком виде выгрузить?

     За 01.09.2026 — 14.09.2026 найдено сообщений: 137, служебных событий: 4.
     [ Читать глазами (HTML) ][ Данные (JSON) ]
     [ Назад ][ Главное меню ]

Вы:  нажали «Читать глазами (HTML)»
Бот: [export_-1001234567890_01-09-2026_14-09-2026.html]
     Найдено сообщений: 137, служебных событий: 4
     Откройте файл в браузере.
     [ Главное меню ]
     [ Выбор чатов ][ Выбор даты ]
```

У `/files` после периода появляется выбор вложений:

```
Вы:  01.09.2026 - 14.09.2026
Бот: Какие вложения включить в архив?

     За 01.09.2026 — 14.09.2026 найдено:
     • фото — 24
     • документы — 6
     • голосовые — 3
     [ Все вложения ][ Только документы ]
     [ Фото и видео ]
     [ Назад ][ Главное меню ]

Вы:  нажали «Фото и видео»
Бот: Выгрузить голосовые сообщения?
     [ Да ][ Нет ]
     [ Назад ]
```

Пока вы нажимаете кнопки, диалог живёт в одном сообщении: бот правит его текст и
клавиатуру на месте, поэтому переписка не растёт, а прошлый шаг не остаётся
висеть рядом. Ваши сообщения и команды бот не удаляет — история запроса видна,
как в любой переписке.

Исключение — текст там, где ждут нажатия кнопки: на выборе чата и на выборе
вложений. Номер чата или тип файлов никто не просил писать, сказать о таком вводе
нечего — бот его убирает, а экран оставляет на месте. Там, где номер как раз ждут
— на экране с `telegram_chat_id` и в списке, когда кнопок хватило не на все чаты,
— замечание встаёт на место строки-приглашения в самом открытом экране,
а присланное тоже убирается. Эти экраны длинные: отвечай бот на каждую попытку
новым окном, в переписке копился бы весь список по разу на попытку.

Если вы отвечаете текстом, следующий вопрос приходит под вашим ответом: иначе он
оказался бы выше него. У прошлого окна при этом снимаются кнопки, чтобы вести
дальше могло только нижнее. Так же ведут себя «Главное меню», «Выбор чатов» и
«Выбор даты» под выгрузкой: нужное окно открывается ниже файла, а сам файл
остаётся на месте.

Шаг назад возвращает диалог ровно туда, откуда он ушёл. Если вы попали на шаг,
прислав текст, «К выбору чата» и «К вводу даты» уберут и окно, и сам присланный
`telegram_chat_id` или неудачные даты, а прошлое окно оживёт на своём месте.

Кнопка «Назад» с первого шага убирает окно диалога вместе с вызвавшей его
командой, и на виду снова остаётся прежнее меню — второго не появляется. Если же
ниже меню уже есть присланный текст или выгрузка, всё это история: её бот не
трогает, а меню открывает на месте закрытого окна, внизу переписки.

Команда, набранная руками, ничего выше себя не убирает. `/start` присылает новое
меню, а `/export` и `/files` — новое окно выбора чата, даже если прежнее ещё
висит: стереть команду вместе со старым окном бот не может, и она осталась бы
над пустым местом. Брошенные окна просто теряют кнопки, живым в переписке
остаётся нижнее. Возвращаться в меню, которое оказалось выше брошенного окна,
бот не пробует — «Назад» и «В главное меню» тогда откроют меню на месте
закрытого окна, внизу.

Исключение — та же команда во время своего же диалога: `/export`, когда `/export`
уже идёт. Открытое окно ведёт ровно туда же, поэтому второе такое же не
появляется, а команда убирается — на экране всё остаётся как было. А `/files`
внутри `/export` окно откроет: ведёт оно к другой выгрузке. Такие два окна
стоят в переписке рядом, поэтому окно выбора чата подписано своей командой —
`/export — переписка файлом` или `/files — архив с вложениями`.

Выбранный чат после выгрузки сохраняется: следующий период можно назвать сразу,
не вызывая команду заново.

Чаты идут от самых свежих по дате последнего сообщения, кнопок выводится не
больше двадцати. Отправить `telegram_chat_id` текстом можно на любом шаге —
этот способ работает всегда.

### HTML-страница

Один файл, который открывается двойным щелчком в любом браузере: ни внешних
стилей, ни запросов в сеть. Данные те же, что в JSON, и хронология та же — она
считается один раз в `chronology()`, чтобы форматы не разъезжались.

Выглядит страница как ночная тема Telegram: тёмное полотно, переписка поверх
него пузырями по ширине текста, даты дней и служебные события — одинаковыми
плашками посередине, светлее полотна, иначе они с ним сливались. Саму переписку
щипком не приближают — от этого она ездила в стороны, — а вот снимок и кадр в
окне просмотра увеличиваются как обычно. В шапке — название чата, `telegram_chat_id`, период, сколько
нашлось сообщений и событий, дата выгрузки. Дальше сами сообщения: имя автора
сверху, время в правом нижнем углу пузыря — оно встаёт в конец последней
строки, как в переписке, и своей строки не занимает. Цвет имени у человека всегда один и тот же и подобран
светлым под тёмный фон, так в длинной переписке видно, кто говорит.

Четыре вещи, которые в JSON читаются плохо, здесь показаны по-человечески:

- **Ответы.** Вместо номера сообщения — цитата над текстом: полоса слева,
  полупрозрачная подложка и скруглённые справа углы, как в переписке. Она же
  ссылка:
  щелчок плавно подводит к оригиналу и подсвечивает его синей полосой во всю
  ширину экрана, как в Telegram, а через пару секунд подсветка плавно сходит. Второй щелчок по той же цитате
  подсвечивает снова. Если оригинал в период не попал, так и написано.
- **Правки.** Рядом со временем стоит «изменено», а прежние версии лежат под
  щелчком (тег `<details>`) — обычно читают последнюю.
- **Пересылки.** Строчка над сообщением: откуда, от кого и когда. У снимка,
  кадра, записи и кружка она уходит вбок: сверху её место занято именем автора,
  и две строки подряд смотрелись бы лестницей. Встаёт пометка справа от пузыря
  и вровень с его верхом — у кружка пузыря нет, и она держится его края. На
  узком экране места сбоку нет, и там пометка возвращается на своё обычное
  место над сообщением.
- **Голосовые.** Вшиты в страницу и играют прямо с неё, без архива и без
  интернета. Собраны как в переписке, прямо в пузыре сообщения и без своей
  плашки: круглая кнопка, которая на ходу показывает паузу, дорожка звука
  и строка под ней: до запуска это длина и вес записи, а с запуска — сколько
  прошло из общей длины. Время сообщения стоит с ней на одной высоте. Дорожку рисует не картинка из Telegram (Bot API её не отдаёт),
  а сам браузер: он разбирает вшитую запись на громкости, и то лишь когда до
  неё долистали. По дорожке же и перематывают — как и у кружка, в тишине,
  со звуком обратно на отпускании. В нижнем углу строки троеточие, а слева от
  него — время сообщения, на одной строке с длиной записи. Под троеточием
  скачивание и скорость, ровно как у кружка; меню раскрывается вниз и вправо.
  Над троеточием на время проигрывания появляется крестик: он останавливает
  запись и возвращает её к началу. Сохранение, как и у файлов, сначала
  спрашивает подтверждение.
- **Кружки.** Ведут себя как в переписке: стоят слева, своих кнопок не имеют,
  щелчок включает, второй — ставит паузу. Пока идёт запись, ход показывает
  тонкая линия по самому ободу. Счётчик у нижнего края виден всегда: до щелчка
  он показывает длину записи, а с запуска ведёт счёт от нуля, поэтому в подписи
  под кружком остаются только тип и вес. Стоит взяться за кольцо — на
  паузе или прямо на ходу, — картинка притухает, кольцо сходит с обода внутрь
  и на конце дуги появляется бегунок: им и перематывают, щелчком или ведя по
  кольцу мышью. Размер самого кружка при этом не меняется. На время перемотки
  звук выключается и листаются только кадры: со звуком он идёт обрывками
  и трещит. У незапущенного и у досмотренного кружка кольца нет вовсе — щелчок
  по нему просто включает запись. До щелчка кружок не стоит кадром, а крутится
  молча по кругу, как в переписке, и сверху на нём перечёркнутый динамик: он
  уходит на время просмотра и возвращается, когда запись досмотрели. Крутятся
  только те кружки, что видны на экране, — остальные страница держит на паузе,
  чтобы не греть процессор впустую. Подложки у кружка нет вовсе — в переписке
  его тоже не обводят, — а поля пузыря ему всё же оставлены: без них кружок и
  имя над ним съезжают левее всей остальной переписки. Подписи под ним тоже нет: ход записи стоит табличкой
  слева у нижнего края, время сообщения — такой же справа, а вес показывают
  в окне перед скачиванием, где он и нужен. В нижнем углу кадра троеточие, под
  которым скачивание записи и скорость от 0,5× до 2×; меню раскрывается вверх
  и вправо, чтобы не закрывать то, ради чего его открыли. Над троеточием, в
  верхнем углу, крестик: он останавливает кружок и возвращает его к немому
  прокруту. Появляется крестик с запуском и держится на паузе тоже — уходит
  только по щелчку по нему самому или когда запись досмотрели.
- **Фото.** Видны прямо в переписке, подпись под снимком, как в чате. Пузырь
  такого сообщения меряется по снимку: имя сверху, кадр от края до края без
  полей по бокам, подпись под ним переносится по ширине кадра. Размер —
  тот, в каком снимок снят, но не шире 480 пикселей и не выше их же: мелкий не
  растягивается до мыла, крупный занимает всю колонку. Троеточия у снимка нет:
  скачивают его стрелкой из просмотра. Щелчок
  разворачивает снимок поверх страницы на сером полупрозрачном фоне: сверху
  справа — крестик, снизу справа — поворот и скачивание,
  снизу слева — «Фото 1 из 2» (у видео — «Видео 1 из 2»), автор и время,
  а подпись стоит по центру
  в полупрозрачной плашке по ширине текста — до половины экрана, дальше подпись
  идёт строками, а совсем длинная прокручивается внутри плашки, чтобы не
  наезжать на снимок. Стрелка над плашкой убирает подпись целиком: плашка
  плавно уезжает вниз за стрелкой и так же выезжает обратно, а стрелка
  переворачивается. Сам снимок при этом не двигается: полосу под подпись
  скрипт меряет по её длине и такую же оставляет сверху, поэтому снимок стоит
  посередине экрана и не зависит от того, убрали подпись или нет. У снимка без
  подписи полоса всего лишь под верхние кнопки, и места ему достаётся больше.
  При листании открытая подпись остаётся открытой и заново не выезжает.
  Соседние снимки листаются стрелками по бокам или
  с клавиатуры; стрелка есть только в ту сторону, куда листать есть куда,
  поэтому у первого снимка она одна справа, у последнего — одна слева.
  Поворот кадр только разворачивает, размер у него остаётся прежним, как
  в Telegram: широкий снимок после поворота выходит за края экрана.
  Esc закрывает, как и щелчок мимо снимка.
- **Видео.** На полотне молча крутится по кругу, как в чате: синяя дорожка по
  нижнему краю ведёт прокрут, в верхнем углу табличка со счётчиком вида `00:03`
  и перечёркнутым динамиком, в нижнем — время сообщения. Пузыря и троеточия у
  видео нет: пузырь у кадра такой же, как у снимка, — имя стоит на нём с
  полями, кадр идёт от края до края, а углы ему обрезает скругление пузыря.
  Без подписи кадр остаётся таким же, как в переписке, и пузырь кончается ровно
  на нём. С подписью кадр становится шире: текст идёт под ним и переносится по
  его ширине, а узкая колонка разрывала бы длинную подпись. Щелчок разворачивает его
  тем же окном, что и фото, — со звуком и своим островом кнопок. Остров стоит
  под кадром, а не на нём, иначе кнопки закрывают нижний край картинки: слева
  динамик с громкостью, посередине «играть», справа полный экран, окно поверх
  других и шестерёнка со скоростями от 0,5× до 2× (выбранную отмечает галочка,
  и держится она до следующей смены). Под ними ход записи, дорожка перемотки и
  остаток до конца. Ширина у острова постоянная: в полный экран он иначе
  растягивался во всё окно, и кнопки разъезжались по углам. В полный экран
  уходит сам кадр с островом, а крестик окна остаётся снаружи, поэтому в углу
  кадра появляется свой — он возвращает из полного экрана. Кнопки рисует сама
  страница: у каждого браузера свои, и выглядели бы они везде по-разному. Играть и ставить на паузу можно щелчком
  по кадру или пробелом. Подпись к видео висит поверх нижнего края кадра, над
  островом: своей полосы ей не отводят, иначе кадр с подписью выходил заметно
  меньше такого же без неё. Фото и видео в окне листаются вперемешку, в том же
  порядке, в каком идут в переписке. Крутятся только те видео, что видны
  на экране.
- **Цитата в ответе.** Имя автора, а под ним строка самого сообщения — в одну
  строку и с троеточием на конце: длинное сообщение в переписке тоже обрывают,
  а слово без пробелов иначе вылезало за край пузыря. Ширину цитате задаёт
  имя автора: строка обрывается ровно там, где кончается имя. Если своих слов у
  сообщения нет, вместо «без текста» стоит вид вложения: «Видеосообщение»,
  «Видео», «Фото», «Голосовое сообщение» — у записей с точкой перед названием,
  как в чате. У фото, видео, кружка и гифки слева от строки стоит мини-кадр
  (у кружка круглый). Берёт его скрипт у самого сообщения на странице: у
  снимка — прямо картинку, у видео снимает один кадр на полотно. Вшивать те
  же байты второй раз ради рамки 34 на 34 точки незачем.
- **GIF.** Крутится сама и без звука, как в чате: плеер ей ни к чему.
- **Документы.** Строкой в пузыре: синий кружок с листом, имя файла и его вес
  под ним, время сбоку. Показать таблицу нечем, а щелчок предлагает сохранить
  её — файл уже внутри страницы и уходит на диск после подтверждения. В окне
  подтверждения видно имя файла и его вес.
- **Что не поместилось.** Остаётся строкой с типом, именем, весом и причиной:
  файл тяжелее запаса, не сохранён или пропал с диска. Такие присылает `/files`
  за тот же период.

Вложения вшиваются с запасом: не больше 12 МБ на файл и 28 МБ на страницу,
потому что base64 раздувает вес на треть, а бот не отправит больше 50 МБ.
Готовая страница проверяется ещё раз: если она всё же вышла тяжелее 45 МБ, бот
не отправит её молча, а попросит взять период покороче.

Скрипты на странице есть, но только ради вложений: кружок, дорожка голосового,
меню под троеточием и просмотр фото во весь экран. В файл попадают лишь те, без
которых страница не заработает: переписке из одного текста они не нужны.

Весь текст на странице экранируется: он пришёл от людей, и без этого достаточно
было бы написать в чат `<script>`, чтобы сломать выгрузку читателю.

### Формат JSON

Сообщения и служебные события идут одной хронологией, как в самом
Telegram, и различаются полем `тип`:

```json
[
  {
    "тип": "служебное событие",
    "событие": "участника добавили",
    "дата": "14.09.2026 14:20:05",
    "кто": "Иван Петров (@ivan)",
    "с кем": "Мария Иванова (@maria)",
    "подробности": "нет",
    "закреплённое сообщение": "нет"
  },
  {
    "тип": "сообщение",
    "отправитель": "Иван Петров (@ivan)",
    "текст": "Отчёт за август",
    "дата отправки": "14.09.2026 14:47:49",
    "была ли отредактирована": "да",
    "ответ на": {
      "telegram_message_id": 10,
      "отправитель": "Мария Иванова (@maria)",
      "текст": "Пришли, пожалуйста, отчёт",
      "дата отправки": "14.09.2026 14:31:02"
    },
    "переслано из": {
      "тип источника": "канал",
      "источник": "РБК (Редакция)",
      "id источника": -1001234567890,
      "дата оригинала": "01.08.2026 12:00:00",
      "автопересылка из канала": "нет"
    },
    "история правок": [
      {
        "текст": "Отчёт за июль",
        "заменено": "14.09.2026 14:52:10"
      }
    ],
    "список вложений": [
      {
        "тип": "документ",
        "файл": "storage/attachments/-1001234567890/5_отчёт.xlsx",
        "имя файла": "отчёт.xlsx",
        "размер": "412,6 КБ"
      },
      {
        "тип": "голосовое сообщение",
        "файл": "storage/attachments/-1001234567890/6_voice.oga",
        "имя файла": "имени нет",
        "размер": "118,2 КБ",
        "длительность": "0:42"
      }
    ]
  }
]
```

Выгрузку читают люди, поэтому пустых мест и технических `null`, `true` и `false`
в ней нет: вместо них стоят слова — `не ответ на сообщение`, `не пересылалось`,
`правок не было`, `да` и `нет`.

У событий входа и выхода поля `кто` и `с кем` совпадают, когда человек
сделал это сам, и различаются, когда его добавили или исключили, — в формулировке
события это уже учтено. `подробности` хранят то, что зависит от события: новое
название чата, отрывок закреплённого текста, новый `telegram_chat_id` после
переезда в супергруппу.

### Время и часовые пояса

В базе время хранится в UTC — так его не ломает переход на летнее время и переезд
сервера. Пользователю оно показывается в поясе из `DISPLAY_TIMEZONE`, и в этом же
поясе понимаются границы запрошенного периода: `14.09.2026` — это сутки по местному
времени, а не по UTC. Поэтому сдвиг часового пояса не «съедает» сообщения на краях
периода.

Команда `/files` нужна тем, у кого нет доступа к серверу: она присылает сами файлы.
Внутри архива вложения разложены по папкам с датами, а файл `список_вложений.txt`
связывает каждый файл с автором и временем сообщения. Если архив не влезает в лимит
Telegram на отправку, он разрезается на части. Про файлы, которые отправить не удалось
(удалены с диска или слишком велики), бот пишет отдельным сообщением.

## Ограничения Bot API

Сбор идёт через обычного бота, а не через юзербот, — отсюда несколько ограничений,
о которых лучше знать заранее.

- **Нет истории.** Бот видит только сообщения, отправленные после его добавления в чат.
  Выгрузить переписку за период до этого момента невозможно.
- **Файлы до 20 МБ.** Больше Bot API боту не отдаёт. Такое вложение не скачивается,
  в лог пишется предупреждение, само сообщение при этом сохраняется.
- **Отправка до 50 МБ.** Поэтому `/files` и разрезает большие архивы на части.
- **Частые запросы Telegram ограничивает** ответом `429`. Вложения скачиваются внутри
  обработчика сообщений, поэтому залп файлов в чате стал бы залпом загрузок: коллектор
  обрабатывает не больше `CONCURRENT_UPDATES_LIMIT` обновлений одновременно
  (`app/collector/runner.py`), остальные ждут своей очереди у Telegram.
- **Privacy mode должен быть отключён**, иначе бот не увидит сообщения в группе.
- **Удаление сообщений не отслеживается** — Telegram не присылает ботам такие апдейты.
  Удалённое в чате сообщение остаётся в базе и попадает в выгрузку как обычное,
  без пометки: отличить его от живого нельзя.

## Про реакции

Реакции не собираются. Модель `Reaction` и функции `create_reaction` / `delete_reaction`
в базе оставлены, так что вернуть сбор можно без миграций — через апдейт
`message_reaction`, но для него бота нужно делать администратором чата и явно
перечислять этот тип апдейтов в `allowed_updates`. Практической пользы для выгрузки
переписки в реакциях нет, поэтому сбор отключён осознанно.

## Безопасность

- `.env` и содержимое `storage/attachments/` исключены из репозитория.
- Админский бот не отвечает никому, кроме ID из таблицы `admins`.
- При сборке архива путь каждого вложения проверяется на выход за пределы
  `storage/attachments/`, чтобы битая запись в базе не превратилась в чтение
  произвольного файла с диска.
